# Research Validation Matrix

Use this matrix to select checkpoint-specific evidence. Repository-specific tests remain authoritative.

| Stage | Minimum evidence | Common failure signals |
|---|---|---|
| Data acquisition | stable source identifier, version/date, permitted checksum, schema, row count | silent source revision, wrong vintage, incomplete download |
| Parsing/ingestion | type checks, parse failures, row count, key coverage | locale/date errors, truncation, encoding loss |
| Cleaning | before/after counts, missingness, outlier handling, exclusion reasons | undocumented drops, unit mismatch, accidental coercion |
| Join/linkage | key uniqueness, match rate, unmatched cases, multiplicity | many-to-many explosion, duplicate keys, biased attrition |
| Sample construction | attrition table, rule-by-rule counts, design correspondence | inclusion rule drift, conditioning on outcomes |
| Variable construction | units, range, missingness, boundary cases, hand checks | sign reversal, denominator error, look-ahead |
| Descriptive analysis | denominators, weighting, subgroup coverage, reproducibility | inconsistent populations, hidden filtering |
| Estimation | formula/specification, N, FE, SE treatment, convergence, baseline comparison | sample drift, default SEs, non-convergence |
| Robustness | one variation at a time, baseline delta, rationale | bundled alternatives, selective reporting |
| Simulation | seed policy, parameter grid, repetitions, diagnostic summaries | unstable random state, insufficient repetitions |
| Figure/table | generated by code, source path, labels/units, deterministic rebuild | manual edits, stale numbers, misleading axes |
| Manuscript | claims trace to outputs, cross-references resolve, caveats retained | stale interpretation, table/text mismatch |
| Reproducibility | clean run, locked dependencies, documented entry point, expected outputs | hidden local state, missing environment details |

## Suggested Evidence Commands

Adapt these examples to the repository:

```bash
git diff --check
markplane check
make test
make reproduce
pytest
Rscript scripts/run_analysis.R
quarto render
snakemake --dry-run
snakemake --cores 1 target
```

Record commands and meaningful outcomes in the owning TASK. Do not write only “tests passed”.
