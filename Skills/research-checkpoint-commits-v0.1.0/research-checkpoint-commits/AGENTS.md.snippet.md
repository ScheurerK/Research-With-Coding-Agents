## Research checkpoint commits

When `.markplane/` exists, use the `research-checkpoint-commits` skill for research, data, analysis, simulation, figure, manuscript, and reproducibility changes.

Require one Markplane TASK to own each scientific Git commit. Read Markplane context before editing, define the checkpoint contract, validate the relevant research invariants, update completion evidence, mark the TASK done, synchronize Markplane, and stage only the coherent checkpoint. Commit messages must include the TASK ID and explain why the change was scientifically or reproducibly necessary.

Do not mix exploratory and confirmatory changes, methodological changes and refactors, or unrelated research stages in one commit.
